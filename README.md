# WON 해결패스 · 인터랙티브 프로토타입
## [데모 보러가기](https://nekerworld.github.io/WON-Solution-Pass/)

2026 우리은행 X SSAFY 아이디어 경진대회(WIN & WON) 본선 시연용 프로토타입입니다.

우리WON뱅킹 안에서 동작하는 AI 에이전트 목업입니다. 두 트랙을 보여 줍니다.

- **트랙 1 · 자산관리**: 목표 상담 → 지표 계산 → 방향 제안 → **고객이 상품 선택** → 가입 지원
- **트랙 2 · 상품**: 상품 선택 → 가입 지원 (**AI와 함께** 또는 **직접 가입**)

자산 분석은 가입의 필수 관문이 아닙니다. 두 트랙과 두 가입 방식은 같은 고객 상태·상품·정책 데이터를 씁니다.

역할은 다음과 같이 나눕니다.

| 담당 | 하는 일 |
| --- | --- |
| AI (모의) | 고객 말 이해, 필요한 질문, 제약 해석, 도구 선택, 설명, 상담 요약 |
| 규칙·코드 | 조건 판정, 지표 계산, 경로 탐색·순환 감지, 상태 전이, 완료 판정 |
| 은행 (가상 API) | 실제 처리와 결과 확정 |

AI는 은행 조건을 만들지 않습니다. 업무는 은행이 허용한 기존 업무 화면을 모달로 열어 처리하고, 모달을 닫으면 결과와 관계없이 은행 기록을 다시 조회해서 다음 단계를 정합니다. 가입은 고객이 직접 승인해야 요청되고, 은행 결과로만 완료를 표시합니다.

> **고지** — 이 프로토타입은 실제 은행 시스템과 연결되어 있지 않습니다. 고객 정보·상품·금리·가입 조건·금액은 모두 시연을 위해 만든 **가상 데이터**이며 실제 우리은행 정책이 아닙니다. 외부 API나 LLM을 호출하지 않으며, AI 응답은 규칙 기반 모의 응답에 로딩 연출을 붙인 것입니다.

## 기본 시연 순서

### 트랙 2 · AI와 함께 가입 (프리셋: 기본 첫 거래)

초기 상태: 우리은행 첫 거래 고객. 만 19세 이상만 충족하고, 실명확인·입출금 계좌·고객정보 확인·인증서가 없습니다. 마이데이터로 다른 은행 계좌가 연결되어 있습니다.

1. 홈 → **상품 가입** → **WON 목돈마련 적금** → **AI와 함께 가입** → **동의하고 시작**.
2. AI가 은행 기록으로 조건을 확인하고 체크리스트(충족·미충족·미확인·처리 중)를 보여 줍니다. 다른 은행 계좌와 휴대폰 명의는 은행이 이미 알고 있어서 묻지 않습니다.
3. "실물 신분증이 있나요?" → **아니요, 없어요** (또는 "신분증은 없고 모바일 신분증은 있어요"라고 입력). 경로 결정에 꼭 필요한 질문만 합니다.
4. 대체 수단 **모바일 신분증 실명확인**이 추천됩니다. 선택하면 기존 업무 화면이 모달로 열립니다 → **진행하기** → **닫고 은행 기록 확인**.
5. 은행 기록을 다시 조회해 남은 조건(입출금 계좌 → 인증서·고객정보 확인)을 같은 방식으로 해결합니다.
6. "가입 준비가 끝났어요" → **가입 정보 확인하기** → **가입 승인** → 확인 모달. 준비 완료와 가입 완료를 구분해 표시합니다.
7. 은행이 `SUCCESS`를 돌려준 경우에만 **가입이 완료됐어요**와 가입 번호가 표시됩니다.

### 트랙 2 · 직접 가입 (비교용)

같은 프리셋에서 상품 상세 → **직접 가입**. 기존 가입 화면처럼 단계마다 조건을 확인하고, 부족하면 **첫 번째 미충족 조건 하나만** 안내합니다. 고객이 전체 메뉴에서 직접 해결한 뒤 **1단계부터 다시** 진행해야 합니다. 시연 패널의 *AI vs 직접 가입 비교*에 질문·입력 단계, 업무 화면 이동, 다시 시작 횟수가 표시됩니다(프리셋을 바꿔도 비교 기록은 유지됩니다).

### 트랙 1 · 자산관리 → 상품 선택 → 가입 지원

1. 홈 → **AI 자산관리 상담** → 동의 → "2년 뒤 집 살 때 보탤 목돈 마련".
2. 연결 기관 조회 결과에 출처(조회·진술·추정·미확인)를 붙이고 고정 공식으로 지표를 계산합니다.
3. 부족한 정보만 묻습니다(최대 3회): 목표 금액 "3천만원 정도" → 예정된 목돈 지출 "경조사 300만원 정도".
4. 필요 월 적립액 131만원이 무리 없는 적립 여력 98만원보다 많아 조정안을 함께 보여 줍니다 → **기간을 3년으로 늘리기**(월 87만원).
5. **이 방향으로 할게요** → **상품 둘러보기**. 상담에서 정한 방향(목돈 마련 · 월 87만원 · 36개월)을 이어받아 상품을 보여 주고, 고객이 직접 고릅니다.
6. 상품을 고르면 가입 지원으로 넘어가며, 가입 정보 화면에 상담에서 정한 금액·기간이 기본값으로 들어갑니다.

질문 중에는 **잘 모르겠어요 / 답하고 싶지 않아요 / 질문은 그만하고 지금 정보로 알려줘**를 언제든 고를 수 있습니다. 모름·거부는 재계산 없이 미확인으로 기록하고 제안 가능 여부를 판단합니다.

## 예외 시나리오 (시연 패널 프리셋)

프리셋을 누르면 데모를 초기화한 뒤 해당 가상 상태를 설정합니다.

| 프리셋 | 상태 | 기대 동작 |
| --- | --- | --- |
| 기본 첫 거래 | 첫 거래 고객 | 신분증 없음 → 대체 수단 → 모달 → 재조회 → 승인 → 결과 |
| 모두 충족 | 조건 모두 충족 | 질문·업무 없이 바로 가입 준비 완료 |
| 순환 | 다른 은행 계좌 없음 | "없어요" → 계좌↔인증서 순환 감지 → 상담 연결(요약·동의·접수) |
| 처리 지연 | 다음 업무가 처리 중으로 남음 | 예외 → **처리 결과 다시 확인** → 재확인 |
| 완료 불일치 반복 | 업무 화면은 완료, 은행 기록 미반영 | 같은 조건 2회 반복 시 같은 업무를 다시 시키지 않고 상담 연결 |
| 결과 불명 | 가입 결과 `UNKNOWN` | 재신청 없이 결과 조회만 허용. 패널의 **은행 확정 SUCCESS/FAILED** 후 조회 |
| 정보 부족 | 소득·지출 미확인 | "잘 모르겠어요" → 최소 정보 부족으로 제안 보류 → 정보 다시 확인·상담 |
| 상담 접수 실패 | 상담 접수 `FAILED` | 요약 생성과 접수 완료를 구분하고 후속 경로 안내 |

그 밖의 패널 기능:
- 은행 사실 스위치, **조회 실패 주입**(조건을 미충족이 아닌 미확인으로 처리), 업무·가입·상담 다음 결과 주입
- **AI 출력 규칙 위반 주입**: 다음 AI 출력에 금지 도구(`submitApplication`)와 완료 단정 문구를 넣어, 검증기가 거부하고 기본 선택지로 대체하는 것을 보여 줍니다.
- 트랙별 상태머신 그래프(원본 워크플로우 / 제안 전이 P1~P8 / 안전 전이 구분), 조건 판정표, 경로 상태 그래프, AI 구조화 출력·검증 추적, 고객 정보 저장소·정정 이력·지표, 이벤트 로그

## 구조 요약

**상태머신 (`WSP.FSM_DEFS`)**
- 트랙마다 전이표가 따로 있습니다: `join`(AI 가입 지원), `direct`(직접 가입), `asset`(자산관리). 표에 없는 전이는 거부되고 로그에 남습니다.
- 각 전이에는 출처가 붙습니다: `D` 원본 워크플로우 화살표, `P1`~`P8` 워크플로우의 빈 분기를 메우는 제안 전이, `S` 중복 요청·결과 불명 등을 막는 안전 전이.
- 가입 지원은 모달 결과 다섯 가지(성공·취소·일부 완료·확인 실패·처리 중)를 재조회 결과에 따라 **조건 충족 / 남은 조건 / 예외** 세 분기로 나눕니다.
- `RESULT_UNCERTAIN`에서는 재신청 전이가 없고 결과 조회로만 빠져나갑니다.

**조건 판정과 경로**
- 조회에 실패하면 모든 조건을 `UNKNOWN`으로 두고, 미충족으로 단정하거나 경로를 만들지 않습니다.
- 업무마다 선행 조건, 효과, 필요한 고객 사정(신분증·모바일 신분증·다른 은행 계좌), 가중치를 데이터로 정의합니다. 가중치는 시연용 가상 값입니다.
- 고객 제약으로 막힌 수단을 거르고, 같은 효과를 내는 대체 수단을 모두 선택지로 보여 줍니다. 확인된 사정만으로 경로가 있으면 질문하지 않습니다.
- 경로가 없으면 원인(순환·수단 없음)을 찾아 상담으로 넘깁니다. 업무 완료 후 같은 조건이 2회 연속 반영되지 않으면 반복으로 판정합니다. 둘 다 AI가 아니라 코드가 판정합니다.

**자산관리 지표 (고정 공식, 이자 제외)**
- 월 여유자금 = 소득 − 지출 − 부채 상환액, 무리 없는 적립 여력 = 여유자금 × 70%
- 남겨 둘 비상자금 = 월 지출 × 3개월, 목표에 쓸 수 있는 예금 = max(0, 예금성 자산 − 비상자금)
- 필요 월 적립액 = (목표 금액 + 예정된 목돈 지출 − 목표에 쓸 예금) ÷ 기간 (만원 단위 올림)
- 정보마다 출처와 정정 이력을 남기고, 정정하면 같은 공식으로 다시 계산합니다.

**AI 출력 검증 (`aiSchema`)**
- 모든 AI 응답은 `{ intent, message, actions[] }` 형식이며 허용된 행동 유형(`ASK`, `SET_CONSTRAINT`, `SET_INFO`, `PRESENT_OPTIONS`, `CALL_TOOL`, `PROPOSE`, `HOLD`, `ESCALATE` 등)만 쓸 수 있습니다.
- 경로 계산에 없는 업무 ID, AI가 실행할 수 없는 도구(가입 요청·업무 실행 등), 은행 결과 없이 완료를 단정하는 문구는 거부하고 기본 선택지로 대체합니다.

**가상 은행 API**
- 모든 호출이 지연 시간이 있는 비동기 함수이며, 실패는 조회 실패(`QUERY_FAILURE`)와 업무 거절(`BUSINESS_REJECT`)로 구분합니다.
- 가입 요청은 `requestId`로 멱등성을 보장하고, 은행이 조건을 다시 검사합니다. 결과 조회 함수는 가입 요청을 다시 보내지 않습니다.
- 상담 접수는 `ACCEPTED`/`FAILED`로 응답해, 요약을 만든 것과 실제로 접수된 것을 구분합니다.
- 화면 전환 중 늦게 도착한 응답은 무시하고(`epoch`), 같은 동작의 연타는 막습니다.

**디자인·서체**
- 홈·채팅 화면은 우리WON뱅킹 앱의 화면 구성을 참고해 다시 그렸습니다. 우리은행 심볼·캐릭터 등 CI 요소는 사용하지 않았고, 아이콘은 직접 그린 SVG입니다.
- 서체는 우리금융그룹이 무료 배포하는 **우리다움체**(Light·Regular·Bold TTF)를 배포 파일 그대로 `prototype/fonts/`에 넣어 사용합니다. 우리다움체의 지식재산권은 우리은행에 있으며, 수정·유료 판매와 CI·BI 제작 용도는 허용되지 않습니다. 우리다움체에 없는 글자는 Pretendard·시스템 서체로 표시됩니다.

## 자가 테스트

패널의 **자가 테스트 → 실행** 또는 콘솔에서 `await WSP.selfTest.run()`으로 실행합니다. 실행 전의 은행 상태·세션·상태머신을 저장해 두었다가 끝나면 복원합니다. 흐름 테스트는 화면 이동과 모달만 대체하고 실제 흐름 코드를 그대로 실행합니다.

- 조회 실패를 미충족이 아닌 `UNKNOWN`으로 처리, 조회 실패 시 가입 지원 중단(P3)
- 고객 제약에 따른 경로 필터링, 필요한 경우에만 질문(P4), 은행이 아는 정보는 묻지 않음
- 순환 감지 → 상담 전환, 완료 불일치 2회 반복 → 상담 전환
- 모달을 닫기만 했을 때 완료로 판정하지 않음, 모달 결과 5가지 → 3분기
- AI 가입 지원 주 경로 끝까지, 처리 중 업무 재조회 후 재확인(P2)
- 결과 조회가 가입 요청을 다시 보내지 않음, 같은 `requestId` 중복 가입 없음, 결과 불명 → 조회만 허용
- 늦게 도착한 응답·연타 무시
- 정정된 정보로 지표 재계산과 이력 기록
- 질문 중단 → 제한적 제안, 질문 한도 3회, 모름·거부 → 재계산 없이 제안 가능 판단 → 보류
- AI 출력 검증기의 허용되지 않은 업무·도구·완료 단정 거부, 위반 주입 시 기본 선택지 대체
- 같은 데이터로 AI 경로와 직접 가입의 조건 판정 일치 (은행 사실 16가지 조합)
- 직접 가입: 첫 미충족 안내 → 메뉴에서 해결 → 1단계부터 다시(P6)
- 상태머신 전이표가 원본 워크플로우 화살표를 모두 포함하고, 그 밖의 전이는 제안(P1~P8)·안전(S) 전이뿐인지
- 상담 접수 실패와 요약 생성 구분
